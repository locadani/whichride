# Decision Log

Every product and technical decision, newest at the bottom. Each one records what else was
considered and why this option won. Changing a decision means adding a new row that supersedes
the old one; rows are never rewritten. The full design is in
`docs/specs/2026-10-19-carsharing-compare-design.md`.

| # | Date | Area | Decision | Alternatives considered | Why |
|---|---|---|---|---|---|
| 1 | 2026-10-19 | Product | Compare the cost of **one trip** across Berlin carsharing providers | Price list comparison sites | Existing sites list prices; none answers "which is cheaper for this trip" |
| 2 | 2026-10-19 | Input | Destination from a **shared Google Maps link**, a pasted link, or a typed address/place | Link only | Links are how destinations arrive; typing covers everything else |
| 3 | 2026-10-19 | Platform | **Native Android app first**, website later | PWA only; native + PWA | Share-sheet and `geo:` integration are reliable only natively; PWA share target is Chrome-only and absent on iPhone |
| 4 | 2026-10-19 | Data | **No partnerships, no unofficial APIs**, no live car map | Reverse-engineered provider APIs | Unofficial APIs break terms and change without notice |
| 5 | 2026-10-19 | Cost | No Google Maps Platform; **OpenRouteService** behind our server | Google Maps APIs | Hard free limits; Google budgets only alert, they don't cap |
| 6 | 2026-10-19 | Cost | Quota exhausted → **manual km/minutes entry**; comparison still works | Paid fallback | Spikes degrade the service instead of producing a bill |
| 7 | 2026-10-19 | Privacy | **No routes or locations stored**; coordinates in request bodies, never URLs; no server-side route cache | Server cache of routes | Owner requirement; Cloud Run logs URLs |
| 8 | 2026-10-19 | Prices | **Crowd-updated prices, fully automatic**, from the second user | Owner moderation | The app must simplify the owner's life |
| 9 | 2026-10-19 | Prices | Reporter's edit is a **personal override immediately** | Wait for consensus | Reporter gets correct numbers now; trolls only affect themselves |
| 10 | 2026-10-19 | Prices | Confirmation asked of users **returning from "Open <provider>"**, max once a week | Ask random users | Only someone who just saw the price can confirm it |
| 11 | 2026-10-19 | Prices | Accept with **one other install confirming** and weighted yes > no | Fixed N confirmations | Works with two users |
| 12 | 2026-10-19 | Abuse | **Play Integrity** + install-ID reputation | "Must run a simulation afterwards" | That rule is easy to fake and loses honest reports |
| 13 | 2026-10-19 | Prices | No "what did you actually pay?" prompts | Payment feedback | Too invasive |
| 14 | 2026-10-19 | Prices | Personal discounts (% and €), subscriptions, refuel credits are **device-only** | Shared | They're personal |
| 15 | 2026-10-19 | Owner | Emergency switch is a **server CLI command**, no admin endpoint | Admin role in the app | Nothing to attack |
| 16 | 2026-10-19 | Architecture | **Rust core** shared by Android (UniFFI), web (WASM), server (Axum) | Kotlin Multiplatform; KMP + Rust; separate Kotlin/TS logic | One tested implementation everywhere; web path mature; reuses smoke-tracker server stack; validated by spike |
| 17 | 2026-10-19 | Architecture | Own server, not app → database directly | Firebase / Supabase | Voting rules stay in the Rust core; key still needs a server; no lock-in |
| 18 | 2026-10-19 | Web | **Astro static site**; read-only; Turnstile + per-IP limits + own quota share | Compose for web | SEO and accessibility; Play Integrity doesn't exist on the web |
| 19 | 2026-10-19 | Brand | One `tokens.json` + one `logo.svg` → Style Dictionary → Android and web | Separate assets | Single source of truth |
| 20 | 2026-10-19 | Providers | v1 = **MILES, Bolt Drive, Free2move** | Include station-based (Flinkster, cambio) | Station-based needs a round trip; doesn't fit one-way A→B |
| 21 | 2026-10-19 | Providers | **SIXT share left open**, added later as the test of the add-provider process | Include now | Its details are unverified; it exercises §5.1 for real |
| 22 | 2026-10-19 | Pricing | No automatic parking buffer minutes | +N minutes for Bolt | Owner decision |
| 23 | 2026-10-19 | Map | No map in v1; **Open in Google Maps** | In-app map | Free, no key, YAGNI |
| 24 | 2026-10-19 | i18n | English, Italian, German, Turkish | English only | Owner's audience |
| 25 | 2026-10-19 | Release | Closed test with **Berlin carsharing users** as testers | Paid testers; tester exchanges only | Real feedback; their confirmations start the crowd prices |
| 26 | 2026-10-19 | Name | App and repo named **whichride**; public repo github.com/locadani/whichride | `carsharing-compare`, `rideprice-comparator`, `fareview` | General enough for rides, scooters and more providers; portfolio |
| 27 | 2026-10-19 | Scope | Airport/zone fees are **not** in milestone 2; moved to a later milestone | Building them now with the link parsing | Owner decision: not needed yet (YAGNI) |
| 28 | 2026-10-19 | Crowd prices | Vote weight = age points (20 new, +1/day, max 100) × smoothed accuracy `(matching+1)×100/(decided+2)` | Equal weights; age only | New installs weigh little; installs that voted against outcomes lose influence; integer-only |
| 29 | 2026-10-19 | Crowd prices | Acceptance: ≥1 other install confirms with weight > 0, and reporter + weighted yes > weighted no; last vote per install counts; reporter's own votes ignored | Reporter excluded from the sum; every vote counts | Works from the second user; repeat votes and self-confirmation add nothing |
| 30 | 2026-10-19 | Crowd prices | Ask at most every 7 days; a price is "not recently confirmed" after 14 days | 30 days | Prices change often (dynamic pricing); weekly asking stays unintrusive |
| 31 | 2026-10-19 | Core | Coordinates as integer 1e-7 degrees parsed from text; short links only detected in the core, expanded by the server | `f64` coordinates; expanding in the app | No floats in the core (same results everywhere); expansion needs the network |
| 32 | 2026-10-19 | Abuse | Install identity: the server issues a random install ID and a 256-bit bearer token at registration; it stores only the token's SHA-256. The app keeps the token encrypted with an Android Keystore key. | A Keystore key pair signing every request | Play Integrity already binds every write to a genuine app and to the exact request (§7.4); the token only has to say *which* install. Signatures would add per-request crypto on both sides and no protection the integrity token does not already give. |
| 33 | 2026-10-19 | Abuse | Play Integrity on **registration, reports, votes and confirmations** (standard requests, `requestHash` = SHA-256 of method, path and body). Routing, geocoding, autocomplete and short-link expansion need a registered install's token and per-install rate limits, not a fresh integrity token. | An integrity token on every routing and autocomplete call | Only genuine apps can register, so only they can use the quota (§8). Autocomplete fires per keystroke; a Google round trip each time would add latency and spend the Play Integrity daily allowance. |
| 34 | 2026-10-19 | Prices | Provider data (name, Android package, refuel credit) comes from `crates/server/catalogue.json`, compiled into the binary; offer prices live in Postgres, seeded from that file only for offers the database does not have yet. | Everything in the database; everything in the file | Matches §5.1: providers change by pull request, prices change by crowd reports. A redeploy never overwrites crowd prices. |
| 35 | 2026-10-19 | Server | SQL with runtime-checked `sqlx::query` and `FromRow`, every query covered by tests against a real Postgres. | `query!` macros with committed `.sqlx/` metadata (smoke-tracker) | Tests against Postgres check constraints, locking and results, not just column types; no generated metadata to keep in sync. |
| 36 | 2026-10-19 | Crowd prices | A "no" without a value on the **current** price is recorded nowhere and changes nothing; only a report with a value can change a price. | Count it against the current price | §7.2 defines −1 for reports; a current price has no rule that a −1 could trigger, and an unused counter is a stored fact with no purpose. |
| 37 | 2026-10-19 | Crowd prices | The confirmation question about a pending change is about the **oldest pending report** of that offer; the catalogue shows its values to every install, but comparisons use them only for the reporter. | Show nothing pending | §7.2's question has to show the values being confirmed. |
| 38 | 2026-10-19 | Crowd prices | Identical rate cards reported again for the same offer become a **yes vote** on the existing pending report, not a second report. | Separate reports | §7.2: "a vote for that value (new report or support for a matching one)". |
| 39 | 2026-10-19 | Crowd prices | When a report is accepted, every other pending report of the same offer is **superseded**; installs' accuracy is settled for all of them (yes matched on the accepted one, no matched on the superseded ones). | Leave them pending | Only one value can be the price; stale reports would ask questions about values nobody sees. |
| 40 | 2026-10-19 | Infra | Production runs in its **own Google Cloud project and Neon project**, with a copy of smoke-tracker's Terraform module extended for extra secrets. | Share smoke-tracker's project | Separate blast radius, budget and IAM; the public repo stays self-contained. |
| 41 | 2026-10-19 | Android | Android application ID **`io.github.locadani.whichride`** (the server's default `ANDROID_PACKAGE` in production). | `app.whichride`, `dev.locadani.whichride` | The reverse of a domain the owner controls (locadani.github.io); a Play application ID can never change. |
| 42 | 2026-10-19 | Product | The user **marks which offers are near them** (toggle chips per offer, grouped by provider; a provider name marks all its offers); the cheapest *marked* offer is highlighted, unmarked ones stay visible below. Marks live on the device for 15 minutes and are never sent. | Official availability feeds; ranking all offers only | No operator publishes an official Berlin feed (`docs/research/2026-10-19-vehicle-availability-feeds.md`) and #4 rules out unofficial APIs; the cheapest offer overall is useless if no such car is nearby. |
| 43 | 2026-10-19 | Data | Revisit official availability feeds if the **IVSG reform** makes sharing operators publish data through Mobilithek | Wait for nothing | It would give nearby cars legally, without breaking #4; status of the law unconfirmed on 2026-10-19 |
| 44 | 2026-10-19 | Abuse | Integrity `requestHash` of reports, votes and confirmations = SHA-256 of `"{METHOD} {PATH}\n{install_id}\n"` + body; registrations send a random client nonce (`"{METHOD} {PATH}\n"` + body); each integrity token is accepted **once** (its SHA-256 remembered in memory for 11 minutes). Supersedes the binding part of 33. | Method, path and body only (33) | Without the install ID, one genuine token could be sent with another install's bearer for the same vote; without a nonce, every registration had the same hash; without the once-only rule a token could be replayed for its 10 minutes of freshness. |
| 45 | 2026-10-19 | Abuse | No IP addresses: registrations are capped **globally** (600 an hour for all clients), signed writes **per install** (120 an hour), both checked before Play Integrity is asked; malformed tokens never reach Google. | Per-IP limits | Spec §9 keeps no network identifiers; the caps protect the Play Integrity daily allowance, and a genuine user never comes near them. |
| 46 | 2026-10-19 | Owner | The owner can **hide** crowd-created offers (out of the catalogue, crowd input refused like a lock) and **close** pending reports from the CLI, settling nobody; an install has at most **one pending proposal per provider**. | Deleting rows; unlimited proposals | Abuse is undone without losing history; one proposal per install per provider stops one install from flooding the proposal list. |
| 47 | 2026-10-20 | Prices | The refuel/charge credit is **entered by each user per provider** and kept on the device with their other adjustments; the catalogue has no refuel credit. Supersedes the refuel part of 34. | A provider default in `catalogue.json`; crowd-reported like prices | Providers don't publish it and it varies between users, so there is no default to seed; decision 14 already kept it device-only. |
| 48 | 2026-10-20 | Providers | v1 = **MILES, Bolt Drive, SIXT share**; SIXT's "Open" button launches **BVG Jelbi** (`com.trafi.whitelabel.bvg`), the app the owner uses for it. Free2move moves to milestone 8. Supersedes 20. | Free2move in v1; the official SIXT app | The owner has prices for these three; Jelbi is how the owner books SIXT. A per-user choice of app comes in milestone 5. |
| 49 | 2026-10-20 | Prices | Seed prices from the owner's spreadsheet: every km and minute is charged **per started unit**; values the owner doesn't know yet are **0** (Bolt's unlock fee, every minimum charge) and are corrected later. | Wait for every value | Started units are how carsharing usually bills; a missing fee only makes a price slightly low, and the crowd and owner can fix it. |
| 50 | 2026-10-20 | Product | Supersedes #42's interaction: the user **adds the cars near them as options** in two steps, choose provider → tick cars (with "Any <provider> car" and a search box for providers with more than 6 offers) → **Add**. Only added cars are ranked; one line reports cheaper cars not added. Open is disabled until something is added. Device-only, 15 minutes, as in #42. | Toggle chips per offer on the result screen (#42); ticks inside the full list; one global search | Owner tried the prototype: chips don't scale to Bolt's many models, and the owner preferred choosing the provider first over one global search; it matches how the user checks one app at a time. |
| 51 | 2026-10-20 | Design | Colours are the Design canvas's light and dark palettes, as 19 roles named after Material 3's; the app **follows the system theme** and never uses dynamic (wallpaper) colour. Control boundaries use the muted colour (`outline`, ≥ 3:1), dividers keep the canvas line colour (`outline-variant`). Error colours, absent from the canvas, are Material's baseline (`#B3261E`, `#F2B8B5`). | Dynamic colour; one theme; the canvas's line colour for control borders | Dynamic colour would show pairs CI never checked; the canvas's light-mode off switch (white knob on `#CBD4DC`) is 1.5:1, below WCAG 1.4.11 |
| 52 | 2026-10-20 | Design | Fonts **Sora** (text) and **JetBrains Mono** (prices, distances, times), as in the canvas, **bundled** in the app and **self-hosted** on the website from the variable font files of the Google Fonts repository (SIL OFL 1.1) | Google Fonts CDN; Android downloadable fonts; system fonts | No request to a third party carries the user's IP (spec §9; LG München I, 3 O 17493/20, ruled embedding Google Fonts a GDPR breach); works offline and without Play services; looks like the design |
| 53 | 2026-10-20 | Design | Type scale: the canvas's 13 sizes become Material 3's 12 headline/title/body/label roles plus 3 number styles (36/18/12, mono); the 24 px screen title becomes 26 (`headline-medium`). Sizes are `sp` on Android and `rem` on the web. | Exact canvas sizes per screen | A named scale keeps screens consistent; `sp`/`rem` follow the user's font size (spec §11) |
| 54 | 2026-10-20 | Design | Spacing on a 4-point scale (4–40); radii 10/14/16/20/28/full from the canvas; minimum touch target **48 dp** (the canvas's 44 px icon buttons grow to 48) | Canvas's 44 px; every canvas gap as a token | 48 dp is Android's and Material's minimum; a short scale is easier to apply than the canvas's 12 different gaps |
| 55 | 2026-10-20 | Design | Style Dictionary **resolves** `tokens.json`; our own small formatters write the Kotlin (`WhichrideColors` constructors) and CSS (both themes in one file). Generated files are **committed where they are used**; CI rebuilds them and fails on any difference, and fails on any listed colour pair below WCAG AA. | Style Dictionary's built-in `compose/object` and `css/variables` formats; generating at build time | Built-in formats write one theme per file and plain `Color` constants, so a role missing in one theme would compile; committed output is readable in reviews and needs no Node in the Android or Astro builds |
| 56 | 2026-10-20 | Design | **Every graphic value lives in `tokens.json` only** (owner requirement): `logo.svg` holds only the logo's shape (a `<rect>` tile and one stroked `<path>`) and names its colours as `{brand.*}` references, in **fixed brand colours** for both themes; our own ~100-line generator turns it into the vector logo, the adaptive launcher icon (with themed-icon layer) and the favicon; a test fails on any literal colour, `dp` or `sp` in hand-written UI code | Colours written in `logo.svg` and checked against the tokens; `svg2vectordrawable` (last release June 2022); Android Studio's manual import | One place to change any value; reproducible in CI with no unmaintained dependency; a constrained source can't lose detail silently |
